## 3. Fichiers
- Livre : un fichier par section dans `sections/` : `0N-0-intro.md` (`# Chapitre N : Titre`, épigraphe `> « … »`, « Le chemin de ce chapitre », données utilisées), `0N-k-<slug>.md` (`## N.k Titre`, `### N.k.j`), puis **`0N-<k+1>-bilan.md`** (`## Bilan du chapitre N`, sans numéro de section, avec le renvoi 📒 global). **Pas de section d'exercices dans le livre.** Noms courts sans accents. Pour les chapitres complémentaires (6–9) : titre `# Chapitre N : ➕ Titre` + `> 🧭 Chapitre complémentaire …`.
- Cahier : **un seul fichier autonome** `cahier/0N-exercices.md` (gabarit : CONVENTIONS.md §1). Le livre y renvoie par la ligne `> 📒 **Pour s'entraîner.** Cahier, chapitre N : application N.1, exercices N.1 à N.4.` en fin de section (numéros qui existent, éléments **de votre chapitre** seulement). Chaque chapitre : 5 à 10 applications guidées (petites études sur les données, code par étapes ≤ 25 lignes) et 10 à 14 exercices ⭐/⭐⭐/⭐⭐⭐ avec corrigés (calcul à la main + code), chacun relié à une section du livre.
- **Tous les fichiers d'un chapitre du livre sont exécutés ENSEMBLE, dans l'ordre** (espace de noms partagé) ; réimportez ce dont vous avez besoin en tête de fichier ; **aucune dépendance de code entre chapitres**. Le cahier d'un chapitre est exécuté séparément du livre et doit recharger ses données.
- Ne touchez qu'à vos fichiers : `sections/0N-*.md`, `cahier/0N-exercices.md`, `build/fig_ch0N.py`/`build/donnees_ch0N.py` (si besoin), `figures/ch0N-*.png`, `donnees/ch0N-*`. **Ne modifiez pas** `build/donnees3.py`, `build/telecharger_credit.py`, les jeux de données partagés, le Makefile, `build/pdf/*`, `fill.py`. Pas de git, pas de `make`, pas d'`assemble.py`, pas de PDF. Pas d'installation de paquet ; **ne touchez jamais à pandas (3.0.6)**. Utilisez des sous-dossiers privés dans un sous-dossier privé du dossier temporaire partagé (par ex. `$TMPDIR/<votre_chapitre>/`) pour vos scripts temporaires (les autres écrivains partagent ce dossier).

## 4. Données (dans `donnees/`, graines fixes ; la vérité programmée est dans la docstring de `build/donnees3.py`)
Univers : une boutique fictive (la gérante, € ; canaux `Boutique`/`Site`/`Réseaux` ; villes « Ville A… Ville T »). Voir CONVENTIONS.md §3.
- `clients_ml.csv` (12 000 clients, 31/12/2025) : variables d'entrée (`age, ville` (20 modalités), `canal_acquisition, appareil` (15 % manquant), `anciennete_mois, nb_commandes_12m, panier_moyen` (manquant si aucune commande), `montant_12m, recence_jours, nb_retours_12m, satisfaction_moy` (15 % manquante, plus souvent si basse), `nb_tickets_support_12m, programme_fidelite, nb_promos_recues_12m, part_achats_promo, taux_ouverture_email, delai_livraison_moy` (12 % manquant), `categorie_preferee, revenu_zone`) ; cibles `churn_90j` (14 %), `depense_6m` (34 % de zéros, asymétrique), `segment_vrai` (0–3, classe latente pour **valider** le non supervisé, jamais en entrée) ; **piège volontaire de fuite** : `commandes_apres_cible` (commandes des 3 mois suivants : à exclure — c'est le matériel de la leçon sur la fuite d'information). La régression logistique atteint ≈ 0,87 d'AUC sur `churn_90j`, une forêt/un boosting ≈ 0,90 (seuils et interactions) ; avec la colonne de fuite ≈ 0,93.
- `transactions.csv` (60 000 commandes en ligne, 0,8 % de fraude, deux types) pour le chapitre 6 et pour le déséquilibre (ch. 4).
- `interactions.csv` (clients × produits, format long, ~6 % de cases non vides, notes pour 25 %) et `produits_ml.csv` pour le chapitre 7.
- `credit_defaut.csv` : **jeu RÉEL** (UCI « Default of Credit Card Clients », CC0, 30 000 clients, 22 % de défaut ; colonnes `limit_bal, sex, education, marriage, age, pay_1…pay_6, bill_amt1…6, pay_amt1…6, default` ; documentation en tête de `build/telecharger_credit.py`). Utilisé pour le chapitre 5 (équité), des « détours sur données réelles » et le projet du cahier. Dites-le chaque fois ; citez la source (Yeh et Lien, 2009).
- Jeux **réels embarqués** (hors ligne) dans scikit-learn : `load_digits` (images 8×8 : t-SNE/UMAP, semi-supervisé), `load_breast_cancer`, `load_wine`, `load_diabetes`. Vous pouvez aussi simuler vos propres données dans le chapitre (graine fixe, déclarée ; script dans `build/` si fichier sauvegardé). **Pas de téléchargement à l'exécution** (tout doit tourner hors ligne).

## 6. Pipeline
Depuis la racine du volume :
`PATH=$PWD/.venv/bin:$PATH DONNEES=$PWD/donnees NO_COLOR=1 OMP_NUM_THREADS=1 .venv/bin/python build/fill.py sections/0N-*.md` (tous les fichiers du chapitre, ordre trié ; **0 erreur exigée**, puis `--check` → « inchangé » : donc **aucun résultat dépendant du temps de calcul, de l'ordre d'un ensemble, ou d'un état non fixé**) puis la même commande avec `cahier/0N-*.md`. Drapeaux de blocs : `hide` (exécuté, absent du livre), `hide-code` (seule la sortie), `noexec`. `python3 build/preview.py sections/0N-*.md` mesure le code visible (plafonds : CONVENTIONS.md §2) ; `--text` montre ce que lira le lecteur.
Rien n'est exécuté dans un blockquote. Sorties ≤ 70 lignes. Ne jamais écrire de ``` dans une sortie ```text. Tout nombre cité dans la prose provient d'un bloc exécuté (caché si besoin) ou d'un calcul à la main écrit en toutes lettres ; **relisez chaque nombre de la prose contre les sorties** (ouvrez la source `.md`, pas l'aperçu). Les résultats qui dépendent d'une bibliothèque (importances, SHAP, UMAP…) peuvent varier légèrement selon les versions : n'écrivez pas de conclusion qui dépende de la dernière décimale.
Figures : produites par des blocs `hide` (`plt.savefig("figures/ch0N-nom.png", dpi=200, bbox_inches="tight")`, style `build/style.py` : BLEU/ORANGE/AQUA/VIOLET/ROUGE, traits fins, étiquettes directes), intégrées par `![légende](figures/ch0N-nom.png)`. **Ouvrez chaque PNG avec Read** (axes coupés, collisions, légendes sur les données) et corrigez. Légendes en français, unités en €.

## 7. Contenu et qualité
- Chaque chapitre du livre ≈ **10 000 à 16 000 mots de texte** (hors code), généreux et agréable : intuition → petit exemple calculé **à la main** (tables de 6–10 lignes) → formalisation et démonstrations (impureté de Gini, variance d'un bagging, gradient boosting comme descente de gradient fonctionnelle, valeurs de Shapley, garantie de la prédiction conforme, équations de Bellman…) → figure(s) → pièges ⚠️ → « À retenir » ✅. - Honnêteté : données simulées vs réelles, limites, ce qui n'est pas exécuté.
